# Sorting 6: Heap Sort 堆排序

> 变种题：#215 数组中的第 K 个最大元素、#347 前 K 个高频元素（见文末进阶）
> 堆本身是独立数据结构，后续堆专题会深挖；这里先把堆排序写出来。

## 题目

实现 `void HeapAdjust(int arr[], int k, int n)`、`void BuildMaxHeap(int arr[], int n)`、`void HeapSort(int arr[], int n)`，对数组原地排序（升序，用**大根堆**）。

## 核心思想

把数组看作一棵**完全二叉树**（下标 1..n，节点 i 的左孩子 2i、右孩子 2i+1），两步：

1. **建堆**：从最后一个非叶子节点 `n/2` 开始，从后往前对每个节点做向下调整，建成大根堆（根是最大值）
2. **排序**：每趟把堆顶（最大值）和末尾交换，堆规模减 1，再对堆顶做向下调整

```
初始数组(1基):  [_, 53, 17, 78, 9, 45, 65, 87]  → 建堆 → 87 到堆顶
第1趟: 87 和末尾 17 交换，堆变 [_, 78, 65, 17, 9, 45, 53]（87 已排好）
第2趟: 78 和末尾 53 交换，堆变 [_, 65, 53, 17, 9, 45]（78 已排好）
... 直到堆只剩一个元素
```

## HeapAdjust 的过程（向下调整）

对节点 k：比较 k 和它的两个孩子，把**最大**的孩子换上来，换下去的孩子继续向下比较，直到不再交换或到叶子。

```
   53                     78
  /  \                   /  \
17    78      →         17   53
/ \   / \              / \   / \
9  45 65 87            9 45 65 87
```

## 面试 / 竞赛考点

- **复杂度**：建堆 O(n)，每趟调整 O(log₂n)，共 n 趟 → **O(n·log₂n)（所有情况都是，没有最坏）**，空间 O(1)
- **稳定性**：**不稳定**（堆顶元素跳远交换）
- **面试必问**：为什么工程上快排比堆排序常用？——堆排序常数大（调整时比较次数多）、缓存不友好（跳着访问），实际性能不如快排。但它**最坏也是 O(n·log₂n)**，所以 `std::sort` 在递归过深时切到堆排序兜底
- **蓝桥杯/面试高频变种**：TopK 问题（见下）

## 进阶变种：第 K 大 / TopK（#215、#347）

堆排序的副产品是堆本身——面试高频题全在这：

| 题目 | 做法 |
|------|------|
| 第 K 个最大元素（#215） | 建**大小为 K 的小根堆**，堆顶就是答案（O(n·log K)） |
| 前 K 个高频元素（#347） | 哈希统计频率 → 建大小为 K 的小根堆（按频率） |
| 海量数据 TopK（面试题） | 内存放不下全部数据时，小根堆只留 K 个——这是堆在"大数据"场景的核心价值 |

关键认知：**求第 K 大/前 K 大，用大小为 K 的小根堆（堆顶是这 K 个里最小的，新元素比堆顶大才进）**；求升序排序才用大根堆。大小根堆的选择是面试常挖的点。
