# Sorting 7: Counting Sort 计数排序（非比较排序）

> LeetCode 对应：#912 排序数组（值域小的情况下可用）
> 蓝桥杯：成绩统计、频次类题目常用思路

## 题目

实现 `void CountSort(int arr[], int n)`，对数组原地排序（升序）。**假设元素都是 0~100 之间的整数。**

## 核心思想

前面的排序都是"比较排序"（通过比较元素大小决定顺序）。计数排序换了个思路：**统计每个值出现几次，然后按顺序放回去**。

三步：

1. **统计**：遍历数组，统计每个值出现次数 → `count[val]++`
2. **累加**：把 count 变成前缀和（`count[i] += count[i-1]`）——此时 `count[i]` 表示"≤ i 的元素有几个"
3. **还原**：从后往前遍历原数组，根据 count 确定每个元素的位置，放回新数组

```
arr = [4, 2, 2, 8, 3, 3, 1]  （元素范围 1~8）

统计:   count[1]=1, count[2]=2, count[3]=2, count[4]=1, count[8]=1
累加:   count = [0, 1, 3, 5, 6, 6, 6, 6, 7]   （count[i] = ≤i 的元素个数）
还原:   从后往前取 arr 元素，arr[6]=1 → 放新数组第 1 位（下标0）……
```

## 和比较排序的区别

| | 比较排序（插入/快排/归并…） | 计数排序 |
|---|---|---|
| 依赖 | 只比较大小 | 知道**值的范围** |
| 时间复杂度 | 至少 O(n·log₂n)（信息论下界） | **O(n + k)**（k 是值域） |
| 空间 | O(1)~O(n) | O(k)（count 数组） |
| 应用场景 | 通用 | 值域小、整数（如成绩 0~100） |

**结论**：值域小时计数排序比任何比较排序都快——这就是"非比较排序"的意义。

## 面试 / 竞赛考点

- **复杂度**：O(n + k)（k 是值域大小），空间 O(k)
- **稳定性**：**稳定**（从后往前还原 + 前缀和定位，保证相对顺序）
- **面试常问**："给 1000 万个 0~100 的整数排序，最快怎么做？"——计数排序 O(n)，比快排 O(n·log₂n) 快得多。这是"看数据特征选算法"的经典考题
- **蓝桥杯**：频次统计（出现次数、众数、成绩分布）常用 count 数组，计数排序是它的完整版
- 计数排序是"基数排序"的基础
