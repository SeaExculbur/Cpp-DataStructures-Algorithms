# C 字符串与指针专项训练（xv6 lab1 暴露的薄弱环节）

> 背景：本组题目针对做 MIT 6.1810 xv6 lab1（sleep/pingpong/primes/find/xargs）过程中暴露的 C 语言薄弱点设计。
> 每题独立成 .c 文件，含任务说明、TODO 填空区和**精确的预期输出**——写完编译运行，输出与预期一致即通过。

## 编译与运行（本目录约定，MinGW）

```
gcc -g t01_strlen.c -o t01_strlen.exe && ./t01_strlen.exe
```

（把文件名换成对应题目即可；t06 需要额外用管道/重定向喂输入，见该文件说明）

## 题目与弱点对照表

| 题目 | 文件 | 针对的薄弱点 | 出处（xv6 里的教训） |
|------|------|-------------|---------------------|
| 1. 指针遍历求长度 | t01_strlen.c | 字符串 = 字符数组 + \0；遍历靠指针 | find 里 `strlen(buf)` 当循环条件 → 无 \0 越界 |
| 2. 拷贝到 \0 | t02_strcpy.c | strcpy 的拷贝语义（拷到源 \0 并补 \0） | 不理解"谁负责 \0" |
| 3. 双指针同步比较 | t03_strcmp.c | strcmp = 两指针逐字符同步遍历 | find 里 strcmp 提取文件名 |
| 4. 路径拼接 | t04_path_join.c | 追加模型：定位 \0 → 覆盖写 → 手动补 \0 | find 拼 buf 的核心模式 |
| 5. 提取文件名 | t05_basename.c | 从末尾扫描找最后一个 '/' | find 的 case T_FILE |
| 6. 逐行读取 | t06_line_reader.c | 累积游标 n + EOF 尾行处理 | xargs 读 stdin |

| 8. 数组 vs 指针数组 | t08_arrays_vs_pointers.c | char a[N][M]（嵌套）vs char *a[N]（指向）| xargs 的 cmd 为什么是指针数组 |

## 做题建议

1. **先看文件头注释**（任务 + 允许/禁止使用的函数）
2. 填空前先在纸上写一遍逻辑，再敲进代码
3. 运行后**逐行对照预期输出**，不一致就找原因（别急着问）
4. 每题做完，用一句话在代码末尾注释里写下"这题教会我什么"——这是刻意组块化的关键一步
5. 全部完成或卡住超过 20 分钟，把 .c 发给 Claude 检查

## 时间估计

t01~t03 各 5 分钟；t04~t06 各 10~15 分钟；t07~t08 各 5 分钟。总约 1 小时。
